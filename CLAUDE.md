# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Run

```bash
# Start full stack (PostgreSQL + Adminer + Web)
cd deploy && docker compose up --build

# Local development (DB must be reachable)
cd src/Songbook.Web
dotnet run

# Publish self-contained Linux binary
dotnet publish -c Release -r linux-x64 --self-contained false
```

## Database Migrations

```bash
cd src/Songbook.Web

# Create migration
dotnet ef migrations add <Name> --context SongbookDbContext
dotnet ef migrations add <Name> --context AuthDbContext --output-dir Migrations/AuthDb

# Apply migrations
dotnet ef database update --context SongbookDbContext
dotnet ef database update --context AuthDbContext
```

`appsettings.json` uses `Host=db` (Docker hostname). Change to `Host=localhost` for local development.

## Architecture

### Two DbContexts, One Database

- **`AuthDbContext`** — extends `IdentityDbContext<ApplicationUser>`, owns only ASP.NET Identity tables (`AspNetUsers`, `AspNetRoles`, etc.)
- **`SongbookDbContext`** — owns all domain data: `Songs`, `Artists`, `Users` (domain profile), `Chords`, `SongChords`, `Playlists`, `PlaylistSongs`

### Identity ↔ Domain User separation

`ApplicationUser` (Identity) and `User` (domain profile in `SongbookDbContext`) are distinct entities linked by `User.IdentityUserId` (unique index to `AspNetUsers.Id`).

`ProfileClaimsPrincipalFactory` runs on every login:
1. Looks up or creates the domain `User` row for the authenticated `ApplicationUser`
2. Injects a `ProfileId` claim (integer, key name `"ProfileId"`) into the principal

Downstream code reads this via `User.GetProfileId()` (`ClaimsExtensions`). Ownership checks use `song.CreatedByUserId == currentUser.GetProfileId()`.

### Authorization

- `AdminOnly` policy (role `Admin`) guards Artists/Create, Edit, Delete
- Songs/Create, Edit: `[Authorize]` + ownership check in the handler
- **Known gap:** `Songs/Delete` has no `[Authorize]` and no ownership check (documented TODO)

### Razor Pages pattern

PageModels contain EF Core queries directly — no repository or service layer. All queries are inline in `OnGetAsync` / `OnPostAsync`.

### Song content format

Chords are embedded as `[Am]`, `[F#m]` etc. in `Content`. Key fields:
- `Content` — raw text with chord markup
- `ContentPlain` — text stripped of chord tags (generated by `Regex.Replace(content, @"\[[^\]]+\]", "")`)
- **Known inconsistency:** `ContentPlain` is re-generated in the Edit handler but left empty in the Create handler

### Chord diagram system

`Chord` model: `Id`, `Name` (e.g. `Am`), `ImagePath`. Multiple rows with the same `Name` = multiple voicings/fingerings.

`ImagePath` is relative to `wwwroot/` and rendered in views as `src="/@chord.ImagePath"`. Images should live under `wwwroot/images/chords/`.

The `SongChords` M:N junction is **not** auto-populated from song content. `Songs/Details` instead parses chord names from `Content` at request time and queries `Chords` directly by name. The junction table exists for future explicit management.

### Localization

Three cultures: `de` (default), `en`, `ru`. Switch via `?culture=ru` query string or cookie (1-year TTL, set by `SetCulture` page). Resource files in `src/Songbook.Web/Resources/`.

### Seeding

`IdentitySeed.SeedAsync()` runs at startup and creates (if missing):
- Role `Admin`
- User `admin@songbook.local` / `Admin123!` assigned to `Admin` role

### Identity pages

Scaffolded under `src/Songbook.Web/Areas/Identity/Pages/Account/`: Login, Register, Logout. Password requirements: min 6 chars, no special characters required, no email confirmation.

## UI & Styling

Design system in `wwwroot/css/site.css` via CSS custom properties:
- `--sb-bg`, `--sb-bg-card`, `--sb-bg-input` — backgrounds
- `--sb-border`, `--sb-accent` (`#c0392b`), `--sb-accent-h` — red/rock accent
- `--sb-text`, `--sb-text-muted`, `--sb-chord` (`#e8a838`) — text colors

Body has an SVG noise texture overlay. Bootstrap variables are overridden.

**Song text theme** — `data-song-theme` attribute on `<html>` toggles between `dark` / `light` for the song display area. Persisted to `localStorage` key `sb-song-theme` by an IIFE in `wwwroot/js/site.js`.

**Chord interaction** — clicking a `.chord` span in the song text highlights the corresponding `.chord-group` in the `.chord-panel` aside. Implemented via delegated event listener in `site.js`.

## Deploy

`deploy/docker-compose.yml` runs three services:
- **db** — PostgreSQL 16, port 5432, volume `songbook_data`
- **adminer** — DB admin UI, port 8443
- **web** — ASP.NET app (port 5000), built from `src/Songbook.Web/Dockerfile`

Credentials come from `.env` in the `deploy/` directory.

CI/CD: GitHub Actions (`.github/workflows/deploy.yml`) triggers on `main` push, SSHs into the VPS, pulls code at `/srv/songbook/app`, then runs `docker compose up -d --build` in `/srv/songbook/`.
